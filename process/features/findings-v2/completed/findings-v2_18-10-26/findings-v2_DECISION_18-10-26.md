# Findings v2 - INNOVATE Decision Summary (locked, 18-10-26)

Saved from chat so PLAN, VALIDATE and EXECUTE can cite it. Substance is verbatim; nothing here is new. Design owner decisions D1-D15 live in `design/mockups/findings-v2_NOTES.md` (read-only). D-1..D-10 below are the engineering decisions that implement them.

## 1. Chosen Approach

Build Findings v2 as a NEW, self-contained UI module (`apps/web/src/features/review/v2/**`, `features/review/zoom/**`, `styles/findings-v2.css`) in three phases: A (new files only, executable now), B (integration into Variance-locked files after Variance P05 closes), C (dedupe hookup, own commit). Pure logic modules carry the behavior so it is unit-testable; one glue hook connects them to the existing zustand store with no store change.

- **D-1 Test ids (hybrid).** Bar "Ask counsel" = `data-testid="action-counsel"` (plus `data-action="ask-counsel"`); blocking row calls `accept(id)`, non-blocking calls `needsCounsel(id)`. "Close issue" = `action-dismiss` and opens the reason modal (reuse `dismiss-modal`, `dismiss-reason`, `dismiss-note`, `dismiss-error`, `dismiss-save`, `dismiss-cancel`). "Move back to review" = `action-restore` calling `restore(id)`. Change rows: "Ask owner" = `action-counsel` calling `needsCounsel(id, {owners, source})`; "Mark as expected..." = `action-dismiss` opening the modal. `action-accept` is retired; specs that click it are repaired in Phase B (blocking: `action-counsel` gives the same accepted status; non-blocking: a new e2e helper `closeAsRealIssue` in a new fixture `e2e/fixtures/findings-actions.ts`). `finding-row` and `finding-body` are kept; row markup stays `li > button[finding-row] + div[finding-body]`. Specs that scope action clicks inside `finding-body` need a derived repair because the bar sits outside the row. Rejected: hidden alias buttons; full rename.
- **D-2 List.** New root `FindingsPanelV2` (takes a `view` prop) replaces the `aside.fp` body at Phase B. Rejected: wrapping `ChangeRow`; overriding `.row` under `.fv2`; a feature flag.
- **D-3 Pure modules plus one glue hook.** `action-plan.ts`: (row, control) gives a call, a next-row id (from To review, on-screen order) or noop; never calls a toggle on an acted row; "Real issue" hidden on blocking. `groups.ts`: To review = open; Sent = counsel, or accepted and blocking; Closed = dismissed, or accepted and non-blocking; progress "N of M reviewed". `outcome.ts`: simulate the status change on the pre-action `Row[]`, run `questionRows` (counsel-sheet rule) and `reviewGate`, produce the D12 text, e.g. "Sent to counsel · Counsel questions now 1 · Gate still blocked (1)". `use-finding-actions.ts`: plan, await the store action, select the next row (accept and needsCounsel; dismiss selects its own), capture `useReview.getState().toast?.undo`, then `showToast(outcome, thatUndo)`. ## 2. Why This Over Alternatives

- New files first removes the Variance lock as a scheduling blocker: Phase A cannot collide with Variance P05 (which touches e2e, samples, scripts and deploy only), and the risky edits to locked files shrink to a few lines in Phase B.
- Pure modules (action plan, groups, outcome, dedupe, width and zoom math) turn the design decisions into fully automated tests; zero unit coverage exists today for `FindingRow`, `DocPane` and `FindingsScreen`.
- Reusing the store's own toast undo callback avoids touching `state/review.ts` (Variance-locked) and avoids exposing the private `restoreSnapshot` closure.
- Hybrid test ids keep most of the 41 `action-*` references working at page level and confine repair to the retired `action-accept` and the `finding-body`-scoped clicks.
- A side map for AI twins keeps `Row` in the locked `model.ts` and the frozen core `toView` untouched.

## 3. Risk Predictions (vc-predict: CAUTION)

| Risk | Mitigation |
|---|---|
| Outcome drift: the simulated D12 text disagrees with the real store recompute | Phase B store parity test (simulated equals real) |
| `ChangeExpanded` depends on Variance exports that may move in P05 | Thin adapter, a render test, and a re-run after P05 |
| Large swap in `FindingsScreen` | One commit; keep `FindingRow` until green; revert is the rollback |
| ResizeObserver loop in fit-width | `scrollbar-gutter: stable`; ignore changes under 2px |
| `--dz` override misses a `.paper` descendant | Enumerate descendants in the plan; design-probe screenshots at 75/100/150 |
| Cmd/Ctrl +/-/0 hijacks browser zoom outside the review screen | Window listener only while the hook is mounted; ignore typing |

## 4. Key Constraints Accepted

- `state/review.ts`, `model.ts`, `FindingsScreen`, `DocPane` and other Variance-locked files are not edited before Variance P05 closes.
- The dedupe tie rule (rule finding wins id and severity) is provisional until the design owner confirms NOTES Q2.
- Ask counsel keeps today's asymmetry (blocking writes a memory decision through `accept`; non-blocking does not); NOTES Q1 stays open.
- No feature flag: v2 ships as a straight swap, so rollback is a revert of one commit.
- Sample counsel sentences, firm names and the 75% confidence threshold in the mockup are placeholders (NOTES Q3).
